## 为什么留着那三个 DLL（重要）

第一版我按「彻底删除」把逗逗相关 DLL 也搬走了，结果 HUNTERCAMP 进入**每 9 秒崩一次、被服务拉起的死循环**。

Windows 事件日志（`.NET Runtime` / 事件 1026）抓到的原始堆栈：

```
异常信息: System.IO.FileNotFoundException
   在 HunterCampBack.ViewModel.Doudou.DoudouViewModel.GetDoudouWebBaseDir()
   在 HunterCampBack.ViewModel.Doudou.DoudouViewModel+<PushDoudouDir>d__35.MoveNext()
   在 System.Threading.QueueUserWorkItemCallback...ExecuteWorkItem()
```

也就是说：`PushDoudouDir` 是挂在**线程池**上的异步任务，里面调 `GetDoudouWebBaseDir()` 去加载 `DoudouPluginCore.dll`；文件不在 → 抛 `FileNotFoundException` → 这个线程池任务没有 try/catch → **进程直接终止**，然后 `HunterCampService` 的 AutoRestart 把它拉起来，如此往复。

所以：
- **删 DLL = 软件崩溃循环**（不可接受）
- **留 DLL + 删界面/删资源 = 功能看不见、入口没了、点不到、跑不起来**

保留的即这三个（对应副本在 `backup\`）：

| 文件 | 大小 | 作用 |
| --- | --- | --- |
| `HonorDoudouPlugin.dll` | 48.6 KB | 猎人营地 ↔ 逗逗的桥接层 |
| `DoudouPluginCore.dll` | 354.6 KB | 插件核心，`GetDoudouWebBaseDir()` 就是加载它 |
| `DoudouInfrastructure.dll` | 165.6 KB | 依赖库 |

## 具体改了什么

### 1) 前端注入（改的是 `build\index.html`）

原文件已备份为 `build\index.html.orig-bak`，共注入三段内容（三个脚本）：

```html
<style id="hc-nodoudou-css">a[href*="/aicompanion"]{display:none!important}</style>
<script defer src="/static/js/huntercamp-touchpad.js"></script>   <!-- 首页右侧触控板胶囊（第一次改造） -->
<script defer src="/static/js/huntercamp-nodoudou.js"></script>   <!-- 隐藏逗逗入口 -->
<script defer src="/static/js/huntercamp-homecard.js"></script>   <!-- 首页「逗逗陪玩」卡片 → 触控板卡片 -->
```

`build\static\js\huntercamp-nodoudou.js` 做的事：

- CSS 隐藏所有指向 `/gameassistant/aicompanion/*` 的链接（即逗逗入口）
- 移除页面中任何短文本含「逗逗」的行/块
- 拦截 `history.pushState/replaceState`，若路由跳到 aicompanion 就退回首页
- `MutationObserver` 持续生效，防止 React 重新渲染时把入口吐回来

### 2) 资源搬走（155.3 MB）

```
Program\1.1.6.4\Assets\Web                   48 MB / 619 文件   逗逗 WebView 前端（Vue）
AppData\DoudouAI_Honor.exe.WebView2          92 MB / 321 文件   逗逗 WebView2 缓存
Program\1.1.6.4\DoudouAI_Honor.exe           15.5 MB            逗逗陪玩主程序
```

逗逗主程序被搬走后，即使有残留调用也**无法启动**；Web 前端和缓存同步没了。

### 3) 配置关掉

`Xml\HunterCampDoudou.xml`：

```xml
<Doudou HostName="www.doudou.com"  Open="0" Environment='Prod'>
```

### 4) 首页「逗逗陪玩」卡片 → 触控板开关卡片（2026-10-25 追加，v2）

首页底部那排卡片里的第 4 张（原「逗逗陪玩 / 陪你游戏，伴你生活」）现在被换成**触控板开关**：

- 做法：`huntercamp-homecard.js` 找到含「陪你游戏」的 `ModeCardItemBox_container` 卡片，**保留原卡片的 DOM 结构与 class**，只替换图标（渐变线条触控板）、名称（触控板）、副标题（深度优化时自动关闭）和点击行为，所以外观和另外几张卡完全一致。
- 开关走的是原生桥 `window.pcHonorBridge.actionBusiness(base64(JSON))`，消息 `TouchpadGet / TouchpadGetResult / TouchpadSet`（与「猎人武器库」页自带的触控板开关同一套消息，`pageID=GamePerformance`）。
- **状态同步（v2 修正）**：应用启动时会把 `window.webviewBusinessMessage` 挂到 window 上（`injectionWindow()`），C# 的每条回包都走它。脚本包住这个函数截获 `TouchpadGetResult` 的 `data.value`，再每 5 秒主动 `TouchpadGet` 一次，所以卡片显示的开/关始终是系统真实状态（不只靠点击后的本地猜测）。
- **与「深度优化」联动（v2 新增）**：文档级捕获监听首页第 6 张卡上的「深度优化」按钮，被点击时先把触控板关掉（副标题变「深度优化中…」、卡片变暗、期间点击无效），12 秒后自动恢复点击前的状态。
- 旧版的「首页右侧浮窗胶囊」已删除（`index.html` 里的 `huntercamp-touchpad.js` 标签由部署脚本清理，js 文件一并删除），现在首页只有这一张触控板卡片。
- 卡片位置与原逗逗卡一致，不会多出第 7 张卡。
- 调试：控制台 `window.__hcHomeCard.state()` / `.toggle()` / `.deep()`。

## 一键部署（软件升级后用）

**升级 HUNTER CAMP 会重置 `build\index.html`**（脚本标签没了），但两个 `.js` 一般还在。升级后右击以管理员运行：

```
D:\HunterCamp-doudou-removal\一键部署.bat
```

它内部调用 `deploy.ps1`（UTF-8 带 BOM，PS 5.1 才能正确读中文），做的事：

1. 自动提权（不是管理员会自己弹 UAC 重跑）
2. 把两个脚本从 `D:\HunterCamp-doudou-removal\payload\` 补回 `build\static\js\`，顺手删掉旧版胶囊/探针脚本
3. 在 `build\index.html` 的 `</body>` 前补齐缺失的 `<script>` 标签（幂等，已有的不重复加；第一次改之前会留 `index.html.orig-bak.fixed`），并移除旧胶囊标签
4. 确认 `Xml\HunterCampDoudou.xml` 是 `Open="0"`
5. 重跑「搬运逗逗资源」（已搬走则跳过）
6. 重启 HUNTERCAMP

日志：`D:\HunterCamp-doudou-removal\deploy-last.log`（`-Quiet` 模式）或屏上转录。
还原：`deploy.ps1 -Restore` 会把 `index.html` 还原、脚本标签去掉、资源搬回。
